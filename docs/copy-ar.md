# project-arcade — النصوص العربية (مسودة ترجمة v1)

- **Language / اللغة:** Arabic / العربية (ar). Modern Standard Arabic (العربية الفصحى المعاصرة)، وليست لهجة محلية.
- **Date / التاريخ:** 2026-10-20
- **Status / الحالة:** machine-assisted draft — needs native-speaker review (مسودة بمساعدة الآلة، تحتاج إلى مراجعة متحدث أصلي). لم يراجعها أي متحدث أصلي بعد.
- **Direction / الاتجاه:** Arabic is an RTL (right-to-left) language. العربية لغة تُكتب من اليمين إلى اليسار (RTL)، ويجب أن تُعكس الواجهة كلها لهذه اللغة. See the RTL / UI notes below.
- **Digits / الأرقام:** هذا الملف يستخدم الأرقام الغربية 0-9 (مثل 18 و48 و2,000). انظر البند 5 في ملاحظات RTL.

### RTL / UI notes for the code session (role 1)

(Written in English on purpose so the code session can act on it. Not page copy.)

1. **Document direction.** For the `ar` locale, render `<html lang="ar" dir="rtl">` (derive both from the locale in `app/[locale]/layout.tsx`). Let components inherit the direction; do not hard-code `dir` on individual components except where noted below (DELETE, email and password inputs).
2. **Logical CSS only.** Use `margin-inline-start/end`, `padding-inline-start/end`, `inset-inline-start/end`, `text-align: start/end`, `border-inline-start/end`. In Tailwind v4 that means `ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`, `text-start`/`text-end`, `rounded-s-*`/`rounded-e-*`, `border-s-*`/`border-e-*` instead of `ml`/`mr`/`pl`/`pr`/`left`/`right`/`text-left`/`text-right`. Prefer `gap-*` over `space-x-*`. Check absolutely positioned elements (badges, close buttons, the "pre-alpha" tag, dropdown and select popovers, toasts) and any `translate-x` animation.
3. **Mirror directional icons:** arrows, chevrons, back/next buttons ("Back to sign in", "Go back", onboarding Next), breadcrumb separators, progress direction, list-item disclosure chevrons, and the curved return arrow and queue direction in the section 14 illustrations (the line of figures should face and move right-to-left). Use `rtl:-scale-x-100` on the icon or swap `ArrowLeft`/`ArrowRight`. **Do not mirror:** the project-arcade logo/wordmark, media controls, check marks, the clock, the "+" icon, the search magnifier, the shield, and any Latin text or digits inside an illustration ("pre-alpha", "1", "48").
4. **Hard offset shadows.** The neo-brutalism theme uses shadows like `4px 4px 0` (falling bottom-right). In RTL, consider mirroring to `-4px 4px 0` (bottom-left) so the "light source" follows the reading direction; the same applies to the press/hover offset (`translate-x-[2px]` etc.). This is a design call; if adopted, define the x offset as a CSS variable and flip it under `[dir="rtl"]`.
5. **Digits.** Recommendation: **Western digits 0-9** for all Arabic UI (amounts, counts, times, dates, the onboarding "1 of 4", the "{n} / 2,000" counter), because the strings already mix with Latin runs (DELETE, project-arcade, emails) and the audience may be mixed. Force it in code with the numbering-system extension, e.g. `new Intl.NumberFormat("ar-u-nu-latn", ...)` or `{ numberingSystem: "latn" }`; locales such as `"ar-EG"` and `"ar-SA"` (and in some runtimes plain `"ar"`) default to Eastern Arabic digits (٠١٢٣). Eastern Arabic digits are the alternative; whichever is chosen must be used consistently everywhere, including dates and Intl.DateTimeFormat. This file uses Western digits.
6. **Bidi isolation.** Wrap every placeholder value and every Latin run in `<bdi>` (or the Unicode isolates FSI U+2068 ... PDI U+2069): `{amount}`, `{item}`, `{Name}`, `{Lender}`, `{time left}`, `{n}`, `project-arcade`, `pre-alpha`, `DELETE`, `[contact email]` and any email address, `[message removed]`, file names such as `supabase/05-messages-and-deletion.sql`, and `iPhone`/`iPad`. Without isolation, trailing punctuation, currency symbols and slashes jump to the wrong side (e.g. "project-arcade." shows the period at the wrong end, "{n} / 2,000" reorders).
7. **Currency and numbers.** Never concatenate a currency symbol by hand. Use `Intl.NumberFormat("ar-u-nu-latn", { style: "currency", currency: "<code>" })`; the symbol position (often after the number in Arabic locales) and spacing come from the locale, and the output contains bidi marks (U+061C ALM / U+200F RLM) that must not be stripped. The currency code is not stated in copy-en.md (data is hosted in Canada; CAD would be "CA$" / "$ كندي" depending on locale), so this needs a decision.
8. **Arabic punctuation.** Use ، (U+060C) for comma, ؛ (U+061B) for semicolon, ؟ (U+061F) for question mark, and «» for quotes. Any string assembled in code (joined lists, "A / B" labels, "Deleting...") must use these; use `Intl.ListFormat("ar")` for lists. Colons, periods and the three-dot "..." stay as they are.
9. **Plurals: 6 CLDR categories.** Arabic has zero, one, two, few (n mod 100 = 3-10, e.g. 3-10, 103-110), many (n mod 100 = 11-99, e.g. 11-99, 111), other (e.g. 100-102, 200, and fractions). Do not hard-code ranges; let `Intl.PluralRules("ar")` pick the category. Example for hours: 0 ساعة / ساعة واحدة / ساعتان / 3 ساعات / 11 ساعة / 100 ساعة. Use `Intl.PluralRules("ar")` / ICU MessageFormat, or `Intl.DurationFormat("ar-u-nu-latn", { style: "long" })`, to build `{time left}` and anything with `{n}`. The copy is written so `{time left}` is a self-contained noun phrase (number plus unit) and no surrounding word agrees with it.
10. **Second-person gender (flagged).** Arabic marks "you" as masculine or feminine in verbs, imperatives and adjectives. This draft uses **gender-neutral constructions wherever natural** (verbal nouns on buttons such as «إرسال» and «حذف حسابي», impersonal «يُرجى ...», passive voice, first-person checkboxes such as «عمري 18 عامًا أو أكثر»), and **masculine generic singular** elsewhere (imperatives such as «تصفّح» and «أضِف»), which is the common convention in Arabic software UI. Exception: the legal pages (section 8 /terms and section 15 privacy policy) use a formal register with no direct address (passive, impersonal «يجب ...» / «يُرجى ...», and third-person «المستخدم»), so they contain no second-person gender marking. Notifications that mention another user (`{Lender}`, `{Name}`) are written so no verb or pronoun agrees with that person's gender. Needs native-speaker review and a product decision.
11. **Typography.** Do not apply `text-transform: uppercase` or `letter-spacing` / `tracking-*` to Arabic text: letter-spacing breaks the cursive joining between letters. Remove them for `:lang(ar)` (or `[dir="rtl"]`). Avoid italic and synthetic oblique for Arabic.
12. **Font.** The current fonts probably have no Arabic glyphs. Add an Arabic-capable font to the stack for `:lang(ar)` via `next/font/google`, e.g. **Noto Kufi Arabic** for headings and buttons (its blocky shapes fit the neo-brutalism look) and **Noto Sans Arabic** (or IBM Plex Sans Arabic) for body text. Increase line height (about 1.6-1.8 for body), since Arabic has taller ascenders/descenders and diacritics; check fixed-height buttons, badges and the bottom bar for clipping.
13. **Mirrored order.** The onboarding "1 of 4" dots start on the right; Next sits on the left and Skip moves to the top-left (inline-end); swipe-to-next goes left-to-right. Dialog button order flips (primary at inline-end, i.e. on the left). The bottom bar order Home ... Me starts from the right (automatic with flex under `dir="rtl"`).
14. **DELETE input.** The account-deletion confirmation input needs `dir="ltr"` (and `lang="en"`) so the typed text and the `DELETE` placeholder render and caret-move correctly; keep the exact-match comparison. Email and password inputs should also get `dir="ltr"`; their labels stay RTL.
15. **Length.** Arabic strings are often similar in character count to English but can render wider; check «أُعيد بحالة جيدة», «إرسال رابط إعادة التعيين» and the bottom bar labels at phone width.

## 3. كيف يعمل

**عنوان القسم:** كيف يعمل

1. **تصفّح** — ابحث عن المعدّات في الكتالوج: أدوات، وكاميرات، وعُدّة تخييم، وألعاب، وآلات موسيقية، والمزيد. صفِّ النتائج حسب الفئة والمنطقة.
2. **احجز دورك** — أضِف ما تريده إلى قائمة انتظارك. إذا كان مُعارًا حاليًا، يبقى مكانك في الدور محفوظًا. وعندما يصبح متاحًا، يكون الدور عليك.
3. **استعِر** — يوافق المُعير على طلبك، وتتفقان على وقت ومكان التسليم. خذه، واستخدمه، واستمتع به.
4. **أعِد** — أرجِعه بالحالة التي استلمته بها. يسجّل المُعير أنه أُعيد، ويأتي دور الشخص التالي في قائمة الانتظار.

**السطر الختامي:** عندك شيء يجمع الغبار؟ [اعرضه](/list) ودَع غيرك يستفيد منه.

## 4. مقدمة صفحة /list

**العنوان:** اعرض معدّاتك

**المقدمة:** عندك معدّات يسعدك أن تُعيرها؟ أضِفها هنا. الأمر يستغرق دقيقتين: عنوان، وبضع صور، وحالتها، ومنطقتك.

**نصوص مساعدة للحقول**
- **مجانًا أم برسم:** الإعارة مجانية افتراضيًا. إن أردت رسمًا بسيطًا، يمكنك تحديده. أي رسم يُتفق عليه ويُدفع مباشرة بينك وبين المستعير، لا عبر هذا الموقع.
- **قيمة التعويض:** ما يدين به المستعير إذا عاد الغرض تالفًا أو فُقد. اجعلها مبلغًا عادلًا، مثل تكلفة الإصلاح أو تكلفة الاستبدال. يراها المستعيرون قبل أن يرسلوا طلبهم.
- **منطقة الاستلام:** اختر مدينة أو منطقة عامة. لا تكتب عنوانك الدقيق في العرض.

**سطر للطمأنة:** أنت من يوافق على كل طلب. يمكنك الرفض، ويمكنك إزالة العرض في أي وقت.

**الزر:** نشر العرض

## 5. بيان عدم الربحية

**العنوان:** ليس للربح. فقط للإعارة.

يُدار هذا الموقع كمشروع مجتمعي غير ربحي. لا إعلانات، ولا رسوم للمنصة، ولا مدفوعات عبر الموقع. لا نأخذ نسبة من أي شيء، ولا نبيع بياناتك. يمكن للمُعيرين أن يختاروا تقاضي رسم بسيط مقابل غرض ما؛ ويُتفق عليه ويُدفع مباشرة بين الشخصين، لا عبر الموقع.

الفكرة بسيطة: أشياء مفيدة كثيرة تبقى بلا استخدام، وأناس كثيرون يحتاجونها لعطلة نهاية أسبوع. نودّ أن نجمع بين الطرفين.

*(ملاحظة لصاحب الموقع: قبل الإطلاق، تأكّد من الطريقة الفعلية لإدارة المشروع وتمويله، وعدّل سطر «لا نبيع بياناتك» ليتوافق مع سياسة الخصوصية الفعلية.)*

## 6. شرح قيمة التعويض

**العنوان:** ما هي قيمة التعويض؟

لكل عرض قيمة تعويض. هي المبلغ الذي يوافق المستعير على أنه سيدين به للمُعير إذا عاد الغرض تالفًا أو فُقد.

- **المُعيرون** يحددونها عند العرض. اجعلها عادلة: تكلفة الإصلاح أو قيمة الاستبدال.
- **المستعيرون** يرونها قبل إرسال الطلب، فلا مفاجآت.
- **إذا حدث خطأ ما،** يسجّل المُعير أن الغرض تالف عند إعادته، وتُطبَّق قيمة التعويض.
- **الدفع بينكما أنتما الاثنين.** الموقع لا يحصّل المال ولا يحتفظ به، ولا يستطيع فرض الدفع. تحدّثا في الأمر، وكونا منصفَين، وسوّيا المسألة مباشرة.

البلى الناتج عن الاستخدام العادي ليس ضررًا. وعند الشك، التقط صورًا عند التسليم وعند الإعادة.

**النسخة القصيرة (للتلميحات/خطوة الطلب):** قيمة التعويض: ما ستدين به للمُعير إذا عاد هذا الغرض تالفًا أو فُقد. تُسوّى مباشرة بينكما.

## 6a. سؤال قيمة التعويض في /list

**عنوان السؤال:** إذا تلف هذا الغرض أو فُقد، كم يجب أن يدفع المستعير؟

**تسمية الحقل:** قيمة التعويض
**تلميح الحقل:** أدخل مبلغًا. هذا ما يوافق المستعير على أنه سيدين لك به إذا عاد الغرض تالفًا أو فُقد.

**نص المساعدة:** فكّر في تكلفة الإصلاح أو قيمة الاستبدال، أيهما أعدل. يرى المستعيرون هذا المبلغ قبل أن يرسلوا طلبهم، لذا فالرقم الواقعي يشجّع الناس على القبول. الموقع لا يحصّل هذا المال. أنت والمستعير تسوّيانه مباشرة.

**رسالة التحقق:** يُرجى إدخال قيمة التعويض، ولو كانت صغيرة.

## 6b. مربع تأكيد المستعير

يظهر في خطوة الطلب، بجانب قيمة التعويض الخاصة بالغرض.

**مربع الاختيار:** أفهم أنه إذا عاد هذا الغرض تالفًا أو فُقد، فسأدين للمُعير بقيمة التعويض البالغة {amount}، وسنسوّي الأمر مباشرة بيننا.

**نص مساعد تحت المربع:** الموقع لا يأخذ أي مبلغ ولا يحتفظ به.

**رسالة الخطأ إن لم يُحدَّد المربع:** يُرجى تأكيد قيمة التعويض لإرسال طلبك.

## 6c. الأسئلة الشائعة: قيمة التعويض

**من يحدد قيمة التعويض؟**
المُعير، عندما يعرض الغرض. ستراها في العرض قبل أن ترسل طلبك، فتعرفها دائمًا مسبقًا.

**من يحصّل المال؟ هل يتقاضى الموقع أي مدفوعات؟**
لا. الموقع لا يحصّل المال أبدًا ولا يحتفظ به ولا ينقله. إذا سُجّل الغرض على أنه تالف أو مفقود، يسوّي المستعير والمُعير قيمة التعويض مباشرة بينهما. الموقع لا يستطيع فرض الدفع، لذا حافظ على الودّ وكن منصفًا.

**كيف أحدد مبلغًا عادلًا؟**
استخدم تكلفة إصلاح الغرض أو استبداله، أيهما أكثر واقعية. إذا كان الغرض قديمًا، فانظر في سعر غرض مستعمل مماثل. المبلغ المرتفع جدًا ينفّر المستعيرين؛ والمنخفض جدًا يجعلك تتحمّل الخسارة إذا حدث خطأ ما. ملاحظة قصيرة عن حالة الغرض في العرض تفيد الطرفين.

**ماذا يحدث إذا لم يتلف شيء؟**
لا شيء. لا تُستحق قيمة التعويض إلا إذا سجّل المُعير الغرض على أنه تالف أو مفقود عند الإعادة. إذا عاد سليمًا، يسجّله المُعير «أُعيد بحالة جيدة» ولا يدفع أحد شيئًا. البلى الناتج عن الاستخدام العادي ليس ضررًا.

## 16. الرسائل، وحذف الحساب، والتحقق من البريد الإلكتروني، وتسجيل الدخول

### 16a. الرسائل داخل الموقع

**الحالة الفارغة:** لا رسائل بعد. عند الموافقة على طلب، يمكنك الدردشة مع الطرف الآخر هنا.

**زر الإرسال:** إرسال
**تنبيه أعلى المحادثة:** تبقى الرسائل داخل الموقع. لا يظهر عنوان بريدك الإلكتروني للطرف الآخر أبدًا. استخدم الرسائل للاتفاق على وقت ومكان التسليم.
**نصيحة أمان:** التقِ في مكان عام إن أمكن، ولا تشارك تفاصيل شخصية لا داعي لها.
**محادثة مقفلة (قبل الموافقة):** تُفتح المراسلة بعد أن يوافق المُعير على الطلب.
**شريط الإعارة المنتهية:** انتهت هذه الإعارة. لا يزال بإمكانكما تبادل الرسائل بشأن مطالبة بالتعويض عن الضرر.

**خطأ:** تعذّر إرسال رسالتك. يُرجى المحاولة مرة أخرى.
**رابط الإبلاغ في المحادثة:** الإبلاغ عن هذه المحادثة

### 16b. حذف الحساب

**المدخل (إعدادات الحساب، منطقة الخطر):**
- **العنوان:** حذف الحساب
- **النص:** حذف حسابك نهائيًا. لا يمكن التراجع عن ذلك.
- **الزر:** حذف حسابي

**نافذة التأكيد**
- **العنوان:** حذف حسابك؟
- **المتن:** سيؤدي هذا إلى حذف ملفك الشخصي وصورك. ستُزال أغراضك. تبقى سجلات استعارتك على الموقع لكنها تُجعل مجهولة الهوية، فلا تعود مرتبطة بك.
- **تحذير عند وجود إعارات مفتوحة:** لديك أغراض مُعارة أو قيد التنفيذ. يُرجى إنهاؤها أو إلغاؤها قبل حذف حسابك.
- **تسمية حقل التأكيد:** اكتب DELETE للتأكيد
- **الأزرار:** حذف حسابي / الإبقاء على حسابي
- **نجاح:** حُذف حسابك. شكرًا لأنك كنت جزءًا من صالة الأركيد.
- **خطأ:** تعذّر حذف حسابك. يُرجى المحاولة مرة أخرى أو التواصل معنا على [contact email].

(أكّد صاحب الموقع: الأغراض التي عرضتها تُحذف مع حسابك. انظر 17.7 للاطلاع على صياغة النافذة الحالية.)

### 16c. التحقق من بريدك الإلكتروني

**العنوان:** تفقّد بريدك الإلكتروني
**المتن:** أرسلنا رابط تحقق إلى عنوان البريد الإلكتروني الذي سجّلت به. انقر عليه لتفعيل حسابك. (حلّ محله القسم 17.3: لا يُعرض العنوان أبدًا.)
**نص فرعي:** لا تجده؟ تفقّد مجلد البريد العشوائي (spam).
**الأزرار:** إعادة إرسال البريد
**أُعيد الإرسال:** أُعيد إرسال رسالة التحقق. قد يستغرق وصولها دقيقة.
**حد الطلبات:** يُرجى الانتظار قليلًا قبل طلب رسالة أخرى.
**عنوان صفحة النجاح:** تم التحقق من البريد الإلكتروني
**متن النجاح:** أنت معنا الآن. ابدأ التصفح، أو اعرض أول غرض لك.
**أزرار النجاح:** تصفّح الكتالوج / اعرض معدّاتك
**انتهت صلاحية الرابط:** انتهت صلاحية هذا الرابط. اطلب رسالة تحقق جديدة.
**رسالة المنع (إذا حاول مستخدم لم يتحقق من بريده أن يستعير أو يعرض):** يُرجى التحقق من بريدك الإلكتروني أولًا. لن يستغرق ذلك إلا لحظة.

### 16d. تسجيل الدخول / إنشاء حساب

**تسجيل الدخول**
- **العنوان:** أهلًا بعودتك
- **الحقول:** البريد الإلكتروني / كلمة المرور
- **الزر:** تسجيل الدخول
- **الروابط:** نسيت كلمة المرور؟ / أول مرة هنا؟ أنشئ حسابًا
- **خطأ:** البريد الإلكتروني أو كلمة المرور غير صحيحة.
- **خطأ عدم التحقق:** يُرجى التحقق من بريدك الإلكتروني أولًا. إعادة إرسال رسالة التحقق.

**إنشاء حساب**
- **العنوان:** انضمّ إلى صالة الأركيد
- **العنوان الفرعي:** غير ربحي، بلا إعلانات، بلا رسوم للموقع.
- **الحقول:** الاسم المعروض / البريد الإلكتروني / كلمة المرور / المدينة أو المنطقة
- **تلميح كلمة المرور:** 8 أحرف على الأقل.
- **مربع 18+:** عمري 18 عامًا أو أكثر.
- **سطر الشروط:** أوافق على [شروط الاستخدام](/terms) و[سياسة الخصوصية](/privacy).
- **الزر:** إنشاء حساب
- **الرابط:** لديك حساب بالفعل؟ سجّل الدخول
- **الأخطاء:** هذا البريد الإلكتروني مسجّل بالفعل. / يُرجى إدخال بريد إلكتروني صالح. / كلمة المرور قصيرة جدًا. / يجب أن يكون عمرك 18 عامًا أو أكثر للانضمام.

**نسيت كلمة المرور**
- **العنوان:** إعادة تعيين كلمة المرور
- **المتن:** أدخل بريدك الإلكتروني وسنرسل لك رابطًا لتعيين كلمة مرور جديدة.
- **الزر:** إرسال رابط إعادة التعيين
- **التأكيد:** إذا كان هناك حساب مرتبط بهذا البريد الإلكتروني، فرابط إعادة التعيين في طريقه إليك.

- "Write a message before sending." (اكتب رسالة قبل الإرسال.): مقبول. بديل: **اكتب رسالة أولًا.**
- "Messages can be up to 2,000 characters." (يمكن أن تصل الرسالة إلى 2,000 حرف.): مقبول. اعرض العدد المباشر قرب الحد، مثلًا **{n} / 2,000**.
- "No messages yet." (لا رسائل بعد.): مقبول. أضِف: **ألقِ التحية واتفق على وقت ومكان.**
- "This request is closed, so messaging is off." (هذا الطلب مغلق، لذا المراسلة متوقفة.): غيّره إلى **هذا الطلب مغلق، لذا لا يمكنك إرسال رسائل جديدة.** (يظهر للطلبات المرفوضة أو الملغاة فقط)
- "The other person deleted their account, so new messages can't be sent." (حذف الطرف الآخر حسابه، لذا لا يمكن إرسال رسائل جديدة.): مقبول. بديل أقصر اختياري: **حُذف حساب الطرف الآخر، لذا لا يمكنك إرسال رسائل جديدة.**
- الرسائل من حساب محذوف تظهر هكذا: **[message removed]** (يُقترح أن تعرض الواجهة العربية **[حُذفت الرسالة]**، ويحتاج ذلك إلى دعم في الكود؛ انظر الأسئلة في آخر الملف)
- شريط المحادثة التجريبية: **محادثة تجريبية. لا شيء هنا حقيقي أو محفوظ.**

**نسيت كلمة المرور**
- "That link has expired. Request a new one below." (انتهت صلاحية هذا الرابط. اطلب رابطًا جديدًا أدناه.): مقبول، يبقى كما هو.
- "Your password has been updated." (تم تحديث كلمة المرور.): يبقى كما هو. (سُحب الاقتراح السابق "You can sign in now": مسار إعادة التعيين يُبقي المستخدم مسجَّل الدخول على /profile. اختياري: **تم تحديث كلمة المرور، وتم تسجيل دخولك.**)
- تسمية المرسل للرسائل من حساب محذوف: **حساب محذوف**

**خطأ على مستوى الصفحة**
- العنوان: **حدث خطأ ما**
- المتن: **تعذّر تحميل هذه الصفحة الآن. يُرجى المحاولة مرة أخرى بعد قليل.** (يبقى كما كُتب)
- الزر: **إعادة المحاولة**؛ الرابط: **العودة إلى الرئيسية**

## 19. إرسال ملاحظات (الأعطال والأفكار)

منفصل عن الإبلاغ. «إبلاغ» مخصص فقط للإساءة المتعلقة بالأغراض والمستخدمين (القسم 9). «إرسال ملاحظات» مخصص للأعطال والأفكار وأي شيء آخر يتعلق بالموقع نفسه.

**تسمية المدخل (التذييل، وصفحة «حسابي»، والقائمة):** إرسال ملاحظات
**السطر الفرعي للمدخل (صفحة «حسابي»):** وجدت عطلًا أو لديك فكرة؟

**عنوان النافذة:** إرسال ملاحظات
**المقدمة:** project-arcade في مرحلة pre-alpha، لذا تفيدنا ملاحظاتك كثيرًا. أخبرنا بما هو معطّل أو مربك أو ناقص.

**النوع (اختر واحدًا):** عطل / فكرة / غير ذلك
**تسمية حقل الرسالة:** ما الذي يدور في ذهنك؟
**النص الإرشادي في حقل الرسالة (عطل):** ماذا حدث، وماذا كنت تتوقع؟ في أي صفحة كنت؟
**النص الإرشادي في حقل الرسالة (فكرة):** ما الذي يجعل هذا أفضل؟
**النص الإرشادي في حقل الرسالة (غير ذلك):** أخبرنا بأي شيء.
**تسمية حقل الرد (اختياري):** كيف يمكننا الرد عليك؟ (اختياري)
**نص مساعد لحقل الرد:** املأ هذا الحقل فقط إذا كنت تريد ردًا. لن نستخدمه لأي شيء آخر. لا تكتب فيه كلمات المرور أو بيانات الدفع.
**ملاحظة:** عنوان البريد الإلكتروني لحسابك لا يظهر هنا أبدًا. إذا أردت ردًا بالبريد الإلكتروني، فاكتب العنوان الذي تريد أن نستخدمه.

**الأزرار:** إرسال ملاحظات / إلغاء
**النجاح:** شكرًا! أُرسلت ملاحظاتك.
**الأخطاء**
- رسالة فارغة: يُرجى كتابة رسالة أولًا.
- طويلة جدًا: رسالتك طويلة جدًا. يُرجى اختصارها. [limit TBD by the builder] (الحد الأقصى يحدده المطوّر)

- إرسال متكرر: محاولات كثيرة جدًا. يُرجى الانتظار بضع دقائق ثم المحاولة مرة أخرى.

**أين يظهر:** أضِف أيضًا سطرًا إلى النص الصغير أسفل نافذة الإبلاغ (القسم 9): هل وجدت عطلًا أو لديك فكرة بدلًا من ذلك؟ استخدم «إرسال ملاحظات».

## أسئلة تحتاج إلى تنسيق أو دعم في الكود (ملاحظة المترجم)

1. **«[message removed]»:** قاعدة البيانات (`supabase/05-messages-and-deletion.sql`) تكتب نص رسائل المستخدمين المحذوفين بالقيمة الإنجليزية الحرفية `[message removed]`. لكي تعرض الواجهة العربية «[حُذفت الرسالة]»، يجب أن يتعرّف الكود على هذه القيمة ويستبدلها عند العرض. القسمان 15 و17.7 يُبقيان القيمة الإنجليزية لتطابق ما يُعرض اليوم؛ وإذا دعم الكود الاستبدال، تُغيَّر في الملف كله إلى «[حُذفت الرسالة]». في الحالتين يجب عزلها بـ `<bdi>` داخل النص العربي.
2. **كلمة التأكيد DELETE:** تبقى `DELETE` بالإنجليزية لأن الكود يطابق هذه السلسلة حرفيًا. إذا أُريد أن يكتب المستخدمون العرب «حذف»، فذلك يحتاج إلى دعم في الكود. حقل الإدخال يحتاج إلى `dir="ltr"` (ملاحظات RTL، البند 14).
3. **تنسيق {time left} و{amount}:** العربية تحتاج إلى مُدد مثل «ساعة واحدة» و«ساعتان» و«3 ساعات» و«11 ساعة» و«100 ساعة»، أي ست صيغ جمع حسب CLDR (zero, one, two, few, many, other)، ويجب أن يولّدها الكود عبر `Intl.PluralRules("ar")` أو `Intl.DurationFormat`، لا بلصق رقم بكلمة ثابتة. وكذلك {n} في عدّاد الأحرف. المبالغ تحتاج إلى `Intl.NumberFormat` بلغة عربية ونظام أرقام موحّد، وموضع رمز العملة يحدده التنسيق لا الكود. صيغت الجمل بحيث لا تتطابق أي كلمة نحويًا مع {time left} (مثلًا «الوقت المتبقي للرد {time left}»).
4. **{listing / user}:** تحتاج العربية إلى جملتين كاملتين لا إلى تركيب: «الإبلاغ عن هذا العرض» / «الإبلاغ عن هذا المستخدم». الكلمتان مذكرتان هنا، فاسم الإشارة «هذا» لا يتغير، لكن لا ينبغي الاعتماد على ذلك إذا تغيّر المصطلح.
5. **تاريخ الشروط وسياسة الخصوصية:** يقول copy-en.md الآن «Oct 19, 2026»، والترجمة تستخدم هذا التاريخ («19 أكتوبر 2026»). كانت نسخة سابقة تذكر عام 2025، ويبدو أنه كان خطأ مطبعيًا؛ يُرجى أن يؤكد صاحب الموقع. إذا تغيّر التاريخ في الإنجليزية، يجب تحديث الترجمة.
6. **الحجية القانونية حسب اللغة:** عند وجود نسختين إنجليزية وعربية من الشروط، يقرر المحامي أيهما المعتمدة. لم تُضِف الترجمة أي بند بهذا الشأن.
7. **الجنس النحوي:** المخاطَب في العربية مذكر أو مؤنث. هذه المسودة تستخدم صيغًا محايدة حيث أمكن (المصادر على الأزرار، و«يُرجى»، والمبني للمجهول، ومربعات الاختيار بصيغة المتكلم مثل «أتحمّل مسؤولية...» بدل «أنا مسؤول»)، والمذكر العام في بقية الأفعال الأمرية والصفات (مثل «كن منصفًا»، و«كن أول من يعرض»). القسمان 8 و15 (الشروط وسياسة الخصوصية) بصيغة رسمية بلا مخاطبة مباشرة («المستخدم» بضمير الغائب، والمبني للمجهول، و«يجب»/«يُرجى»)، فلا يبقى فيهما تذكير أو تأنيث للمخاطَب. في الإشعارات التي تذكر {Lender} أو {Name} صيغت الجمل بحيث لا يتطابق فعل أو ضمير مع جنس ذلك الشخص (مثلًا «سُجّلت إعادتك ... من قِبل {Lender}» و«يُرجى التواصل مع {Lender}»). كذلك «المُعير» و«المستعير» بصيغة المذكر العام. يحتاج إلى قرار المنتج ومراجعة متحدث أصلي.
8. **الاتجاه من اليمين إلى اليسار (RTL):** انظر قسم «RTL / UI notes for the code session (role 1)» في رأس الملف. أهم النقاط: `dir="rtl"` و`lang="ar"` على عنصر html، وخصائص CSS المنطقية، وعكس الأيقونات الاتجاهية والظلال، وعزل العناصر النائبة والنصوص اللاتينية بـ `<bdi>`.
9. **الأرقام:** التوصية هي الأرقام الغربية 0-9 بشكل موحّد. إذا اختير الأرقام المشرقية (٠-٩)، يجب تحويل كل الأرقام في هذا الملف (18، 48، 8، 60، 80، 500، 2,000، 1 من 4، 6) وفي الكود معًا.
10. **الخط وطول النصوص:** الخطوط الحالية على الأرجح لا تحتوي على حروف عربية؛ يلزم خط عربي (مثل Noto Kufi Arabic أو Noto Sans Arabic) وزيادة ارتفاع السطر، ومنع `letter-spacing` و`uppercase` على النص العربي. يجب فحص الأزرار والشريط السفلي على شاشة الجوال.
11. **علامات الترقيم:** تستخدم الترجمة ، و؛ و؟ و«». أي نص يُركّب في الكود (قوائم، فواصل «/»، علامات استفهام بعد عنصر نائب) يجب أن يستخدم العلامات العربية وأن يُعزل حول النصوص اللاتينية.
12. **الفصحى واللهجات:** النص بالفصحى المعاصرة، لكن بعض الكلمات تختلف بين البلدان (أسماء الأشهر، «جوال/موبايل/محمول»، «البريد العشوائي»). يُستحسن أن يراجعه متحدث أصلي من الجمهور المستهدف.
13. **«تعويض» مقابل indemnity:** المصطلح المختار «قيمة التعويض» قد يتداخل مع المصطلح القانوني «التعويض» (indemnity) في الشروط النهائية. على المحامي التأكد من عدم الالتباس عند صياغة بند التعويض (indemnity).
