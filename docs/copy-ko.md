## 3. 이용 방법

**섹션 제목:** 이렇게 이용해요

1. **둘러보기** — 장비 목록에서 장비를 찾아보세요: 공구, 카메라, 캠핑 용품, 게임, 악기 등 다양해요. 카테고리와 지역으로 필터링할 수 있어요.
2. **줄 서기** — 원하는 물건을 대기열에 넣으세요. 다른 사람이 빌려 간 상태라도 내 자리는 그대로 유지돼요. 물건이 돌아오면 다음은 내 차례예요.
3. **빌리기** — 빌려주는 사람이 요청을 승인하면, 전달할 시간과 장소를 함께 정하세요. 받아서, 쓰고, 즐기세요.
4. **돌려주기** — 받았을 때 상태 그대로 돌려주세요. 빌려주는 사람이 반납 완료로 표시하면 대기열의 다음 사람 차례예요.

**마무리 문장:** 먼지만 쌓여 가는 물건이 있나요? [등록해서](/list) 다른 사람도 써 볼 수 있게 해 주세요.

## 5. 비영리 선언

**제목:** 돈 벌려는 곳이 아니에요. 빌려주는 곳이에요.

이 사이트는 비영리 커뮤니티 프로젝트로 운영돼요. 광고도, 플랫폼 수수료도, 사이트를 통한 결제도 없어요. 어떤 것에서도 수수료를 떼지 않고, 여러분의 데이터를 팔지도 않아요. 빌려주는 사람은 물건에 적은 이용료를 받기로 정할 수도 있어요. 이용료는 사이트를 거치지 않고, 두 사람이 직접 정하고 직접 주고받아요.

이유는 간단해요: 쓸모 있는 물건은 많은데 대부분 놀고 있고, 주말에 잠깐 필요한 사람도 많아요. 이 둘을 이어 주고 싶어요.

*(운영자 메모: 출시 전에 프로젝트가 실제로 어떻게 운영되고 자금을 마련하는지 확인하고, "데이터를 팔지 않는다"는 문장을 실제 개인정보 처리방침에 맞게 조정하세요.)*

## 6. 파손 배상금 설명

**제목:** 파손 배상금이 뭔가요?

모든 게시글에는 파손 배상금이 있어요. 물건이 파손되거나 분실되면 빌리는 사람이 빌려주는 사람에게 내기로 동의하는 금액이에요.

- **빌려주는 사람**은 등록할 때 금액을 정해요. 수리비나 교체 비용처럼 공정하게 정하세요.
- **빌리는 사람**은 요청하기 전에 금액을 확인하니까 나중에 놀랄 일이 없어요.
- **문제가 생기면** 빌려주는 사람이 반납받을 때 물건을 파손으로 표시하고, 파손 배상금이 적용돼요.
- **돈은 두 사람이 직접 주고받아요.** 사이트는 돈을 받거나 보관하지 않고, 결제를 강제할 수도 없어요. 충분히 이야기하고, 합리적으로, 직접 정산하세요.

일반적인 사용 흔적은 파손이 아니에요. 애매할 것 같으면 전달할 때와 반납할 때 사진을 찍어 두세요.

**짧은 버전 (툴팁/요청 단계용):** 파손 배상금: 이 물건이 파손되거나 분실되면 빌려주는 사람에게 내야 하는 금액이에요. 두 사람이 직접 정산해요.

**도움말:** 수리비나 교체 비용 중 공정한 쪽을 생각해 보세요. 빌리는 사람은 요청하기 전에 이 금액을 보니까, 현실적인 금액일수록 선뜻 빌리겠다는 사람이 많아요. 사이트는 이 돈을 받지 않아요. 빌리는 사람과 직접 정산하세요.

## 6b. 빌리는 사람 확인 체크박스

요청 단계에서 물건의 파손 배상금 옆에 표시됩니다.

**체크박스:** 이 물건이 파손되거나 분실되면 빌려주는 사람에게 파손 배상금({amount})을 내야 하고, 두 사람이 직접 정산한다는 점을 이해했어요.

**체크박스 아래 도움말:** 사이트는 어떤 결제도 받거나 보관하지 않아요.

**미체크 시 오류:** 요청을 보내려면 파손 배상금을 확인해 주세요.

## 6c. 자주 묻는 질문: 파손 배상금

**파손 배상금은 누가 정하나요?**
빌려주는 사람이 물건을 등록할 때 정해요. 요청하기 전에 게시글에서 확인할 수 있으니 항상 미리 알 수 있어요.

**돈은 누가 받나요? 사이트가 결제를 받나요?**
아니요. 사이트는 돈을 받거나, 보관하거나, 전달하지 않아요. 물건이 파손 또는 분실로 표시되면 빌리는 사람과 빌려주는 사람이 파손 배상금을 직접 정산해요. 사이트는 결제를 강제할 수 없으니, 서로 친절하고 합리적으로 해결해 주세요.

**공정한 금액은 어떻게 정하나요?**
물건을 수리하는 비용과 새로 사는 비용 중 더 현실적인 쪽을 기준으로 하세요. 오래된 물건이라면 비슷한 중고 물건 가격을 참고하세요. 너무 높게 정하면 빌리는 사람이 망설이고, 너무 낮게 정하면 문제가 생겼을 때 내가 손해를 봐요. 게시글에 물건 상태를 짧게 적어 두면 양쪽 모두에게 도움이 돼요.

**아무것도 파손되지 않으면요?**
아무 일도 없어요. 파손 배상금은 빌려주는 사람이 반납 때 물건을 파손 또는 분실로 표시한 경우에만 내요. 멀쩡하게 돌아오면 빌려주는 사람이 문제없이 반납으로 표시하고, 아무도 돈을 내지 않아요. 일반적인 사용 흔적은 파손이 아니에요.

## 7. 작은 UI 문구 (선택)

- 장비 목록이 비었을 때: 아직 아무것도 없어요. 처음으로 등록해 보세요.
- 대기열이 비었을 때: 대기열이 비어 있어요. 괜찮은 물건을 찾아보세요.
- 빌릴 수 있는 물건: 지금 빌릴 수 있어요
- 대여 중인 물건: 대여 중이에요. 대기열에 줄 서세요.
- 요청 보냄: 요청을 보냈어요. 빌려주는 사람이 답해 줄 거예요.
- 문제없이 반납: 무사히 돌아왔어요. 깔끔해요.
- 파손 반납: 파손으로 표시됐어요. 파손 배상금이 적용되니 빌려주는 사람과 해결하세요.

## 코드 협조가 필요한 사항 (번역자 메모)

1. **"[message removed]":** 데이터베이스(`supabase/05-messages-and-deletion.sql`)는 삭제된 사용자의 메시지 본문을 영어 문자열 `[message removed]` 그대로 저장합니다. 한국어 화면에 "[삭제된 메시지]"를 표시하려면 코드가 이 값을 인식해 표시할 때 바꿔야 합니다. 15절과 17.7절은 지금 실제로 표시되는 대로 영어 원문을 유지했고, 코드가 지원하면 "[삭제된 메시지]"로 일괄 교체합니다.
2. **DELETE 확인 단어:** 코드가 이 문자열을 정확히 비교하므로 영어 `DELETE`를 그대로 둡니다. 한국어 사용자가 "삭제"를 입력하게 하려면 코드 지원이 필요합니다. 현재 문구 "DELETE를 입력하세요"의 조사 "를"은 고정된 단어 뒤라 문제없습니다.
3. **{left}와 {amount} 형식:** 한국어에서는 "5시간", "2일", "30분"처럼 숫자와 단위를 붙여 쓰는 기간 형식이 필요하고, 금액도 언어에 맞는 형식(예: "30,000원" 또는 통화 기호 형식)이 필요합니다. 한국어에는 복수형이 없으므로 복수 규칙은 필요 없습니다. 코드에서 로캘별 형식을 지정해 주세요.
4. **{listing / user}:** 한국어에서도 이어 붙이지 말고 두 문장 전체를 따로 둬야 합니다: "이 게시글 신고하기" / "이 사용자 신고하기".
5. **약관과 개인정보 처리방침 날짜:** 지금 copy-en.md(8절, 15절)에는 "Oct 19, 2026"으로 되어 있고, 번역도 이에 따라 "2026년 10월 19일"로 썼습니다. 예전 버전에 있던 2025년은 오타로 보입니다. 영어판 날짜가 다시 바뀌면 번역도 함께 고쳐야 하니 운영자 확인을 부탁합니다. 업데이트(2026-10-20): 영어판의 두 날짜가 "Oct 20, 2026"으로 바뀌었고 번역도 맞춰 두었습니다. 이 날짜는 여전히 초안용이며, 출시 전에 실제 게시일로 바꿔야 합니다(8절과 15절의 TODO 참고).
6. **법률 문서의 언어별 효력:** 영어판과 한국어판 약관이 함께 있을 때 어느 쪽이 우선하는지는 변호사가 결정할 사항입니다. 번역에는 이에 관한 조항을 추가하지 않았습니다. 한국 이용자를 대상으로 할 경우 한국 개인정보 보호법 적용 여부도 변호사가 판단할 사항이며, 번역에서는 원문에 없는 법령을 추가하지 않았습니다. 업데이트(2026-10-20): 사용자가 번역된 약관 및 개인정보 처리방침 페이지에 비공식 번역이며 영어판이 적용된다는 안내를 표시하기로 결정했습니다(문구는 docs/i18n-legal-notice.md). 이 안내가 각 나라에서 의도한 법적 효력을 갖는지는 여전히 변호사가 판단할 사항입니다.
7. **자리 표시자 뒤 조사 (코드 확인 필요):** 한국어 조사는 앞말의 받침 유무에 따라 형태가 바뀝니다(을/를, 이/가, 은/는, 와/과, 으로/로). 자리 표시자에 무엇이 들어올지 모르므로 이 번역에서는 다음과 같이 처리했습니다.
   - `{Name}`, `{Lender}`: 항상 뒤에 "님"을 붙여(`{Name}님이`, `{Lender}님이`) 조사가 "님"에 붙도록 했습니다. 코드가 이름 뒤에 "님"을 따로 붙이지 않도록 주의해 주세요.
   - `{item}`: 바로 뒤에 조사가 오지 않게 했습니다("{item} 관련", "내 차례예요: {item}.", "{item}: ...").
   - `{amount}`: "파손 배상금({amount})이"처럼 괄호 안에 넣어 조사가 "배상금"에 붙도록 했습니다.
   - `[contact email]`: "[contact email] 주소로"처럼 "주소"를 넣어 으로/로 문제를 피했습니다.
   - `{left}`: 뒤에 "안에", "남았어요"만 와서 조사 문제가 없습니다.
   - 코드에서 문장을 새로 조립하거나 위 구조를 바꿀 경우, 받침을 판별해 조사를 고르는 도우미 함수(예: es-hangul의 josa 함수 같은 라이브러리나 간단한 자체 함수)를 쓰거나 "(을)를", "(이)가" 같은 병기 형식을 쓰는 것을 권장합니다.
8. **한글 글꼴과 줄바꿈:** 한글 글리프가 있는 글꼴이 필요합니다(예: Pretendard, 폴백 Noto Sans KR). neo-brutalism 테마의 굵은 제목 글꼴에 한글이 없으면 시스템 글꼴로 대체되어 스타일이 깨질 수 있으니 굵은 웨이트(700 이상)도 확인해 주세요. 단어 중간에서 줄이 바뀌지 않도록 `word-break: keep-all` 적용을 권장합니다.
9. **문자열 길이:** 한국어는 글자 수로는 영어보다 짧은 경우가 많지만 글자 폭이 넓습니다. "장비 목록 둘러보기", "내 장비 등록하기", "문제없이 반납" 같은 버튼과 배지가 휴대폰 화면에서 넘치지 않는지 확인해 주세요.
10. **"님" 경칭과 사용자 이름:** 표시 이름이 영어인 경우에도 "{Name}님"은 자연스럽습니다. 다만 표시 이름 자체가 이미 "님"으로 끝나는 경우(드묾) 중복될 수 있습니다.
