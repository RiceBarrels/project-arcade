- **Date:** 2026-10-20. Japanese (ja) added 2026-10-21; its Intl facts were checked with `bun -e` (Bun 1.3.9, ICU 74.2) and Node 24.15.0 (ICU 78.3, CLDR 48).

| ar | zero, one, two, few, many, other | **all six** | zero | zero: 0; one: 1; two: 2; few: n%100 = 3-10; many: n%100 = 11-99; other: 100-102, 1000, decimals. Dual nouns also change with grammatical case (شخصان / شخصين). |

Rules for every language:
- Put the **whole sentence** inside each plural branch. Verbs, adjectives and articles agree with the count in es, fr, pt, ru and ar ("Queda 1 / Quedan 2", "Осталась 1 вещь / Осталось 5 вещей").
- Add an exact `=0` branch where the UI can show zero, so empty states read naturally ("Tu fila está vacía", "قائمة انتظارك فارغة", "Твоя очередь пуста."). Where the code already shows a separate string at zero, `=0` is not needed.
- Use `Intl.PluralRules` / an ICU library. Never `n === 1`.

## 3. Sentence types that need special handling

1. **Counts with agreement** (es, fr, pt, ru, ar): the whole sentence goes in each branch. ar also needs the dual in the right case for that sentence.
2. **Gender of {Name} / {Lender}** (es, fr, pt, ru, ar; also vi pronouns): the site stores no gender. Translations already avoid agreeing words (passive voice, present tense, "{Lender}: ...", "esa pessoa"). Code must not build "{Name} + past-tense verb" or add pronouns (他/她, anh ấy/chị ấy). If a gender field is ever added, use ICU `select` with a neutral `other`.
3. **Words attached to {item}** (fr de/d'/du, pt do/da, es del, ru case, ko particles 을/를 이/가, tl linkers -ng/na, ar prefixed prepositions): {item} is free user text, so nothing may be glued to it. Translations put it after a colon, in quotes or after a separate word. Code must not add articles, particles or quotes; if code adds quotes, remove them from the strings.
4. **{listing / user}**: cannot be one template in any language (gender, case, measure word, word order). Use two full strings or `{target, select, listing {...} user {...} other {...}}`. Each `copy-<code>.md` already gives both sentences.
5. **Korean names**: copy-ko.md writes `{Name}님`; code must not add another 님 or a particle.
6. **Arabic duration after a preposition**: copy-ar.md section 10 "ردّ خلال {left}" is wrong for exactly 2 hours or 2 minutes, because Intl gives the nominative ساعتان and after خلال it must be ساعتين. Options: use the narrow form (5 س و12 د), or reword the string so {left} is not after a preposition. Pending native review; copy-ar.md not changed.
7. **Fixed numbers** (48 hours, 18, under 6h, 2,000 characters, 30 days): already written correctly in every file. If any becomes a variable, it needs a full plural message in the case of that sentence (ru "в течение 21 часа / 22 часов").
8. **Bidi** (ar): wrap {item}, {Name}, {amount}, numbers, counters "{n} / 2,000" and Latin words in `<bdi>`. See the RTL notes at the end of copy-ar.md.
9. **Typography** (fr): no-break space before : ; ? ! and inside « », "48 h", "2 000", "25,00 $". `Intl` already uses no-break spaces for numbers; strings need U+00A0/U+202F stored or applied by a formatter. ru: `Intl.DurationFormat` uses ordinary spaces; insert U+00A0 if wrapping matters.
10. **Fragments**: no sentence should be built from translated fragments in English order (zh, ko, tl, ar word order differs). One message per visible sentence.
11. **Legal pages**: /terms and /privacy use a formal register; do not reuse UI strings there (glossary section 4).

## 5. Per-language detail

Checked by a second, independent agent per language. Sample messages use the UI register (informal), not the legal register.

### Simplified Chinese (zh)

- **Categories:** zh / zh-Hans / zh-CN: cardinal = { other } for every number (0, 1, 2, 5, 1.5, 1000). Ordinal = { other }. Chinese has no plural inflection; a count needs a measure word between number and noun (# 人, # 件物品, # 个对话, # 条消息). Verified with Node v24.15.0 Intl.PluralRules('zh-CN'): cardinal and ordinal categories ['other']; select(0/1/2/1.5) = other.
- **Keys:** Only `other`. A plain {count} interpolation is enough; if the shared format requires a plural block, use {count, plural, other {...}}. An exact `=0` branch is optional and only for nicer zero copy (it is not a CLDR category).
- **Sample: people ahead:** {count, plural, other {你前面还有 # 人。}}  With optional zero copy: {count, plural, =0 {你前面没有人了。} other {你前面还有 # 人。}}  (UI register 你). Related: {count, plural, =0 {还没有人排队。} other {有 # 人在排队。}}
- **Sample: items in queue:** {count, plural, =0 {你的队列是空的} other {你的队列里有 # 件物品}}  (the =0 branch is optional; # 件物品 alone for a short counter). The measure word 件 is required in the translated message, not added by code.
- **Zero:** 0 falls in `other`, and 有 0 人在排队 / 0 件物品 are grammatical but mechanical. Prefer an exact =0 branch (还没有人排队 / 你前面没有人了 / 你的队列是空的). For formatTimeLeft at <= 0, show the section 10 expiry message rather than 0 分钟.
- **Fixed numbers:** No agreement changes: 48 hours = 48 小时; 18 or older = 年满 18 岁; under 6h = 少于 6 小时; 2,000 characters = 2,000 个字符; 30 days = 30 天. copy-zh.md puts a half-width space between digits and Chinese (48 小时). Intl output has none (48小时). Pick one convention per surface.
- **Numbers and currency:** zh-CN: Latin digits, comma grouping every 3 digits, '.' decimal. Verified: (2000).toLocaleString('zh-CN') = '2,000', 1234567.89 = '1,234,567.89'. Same visible result as en-US for these values, but pass the locale anyway. 万 grouping is only used in compact notation. Currency, verified: USD = 'US$1,234.50', CNY = '¥1,234.50', CAD = 'CA$1,234.50'. A bare '$' is ambiguous to Chinese readers, so format from the item's currency.
- **Time left:** Chinese has no letter abbreviations. h = 小时, m = 分钟: '5h 12m' = '5 小时 12 分钟' (or '5小时12分钟'), '12m' = '12 分钟', days = 天. Verified: Intl.DurationFormat('zh-CN') narrow/short/long = '5小时12分钟'; NumberFormat unit = '48小时', '12分钟'.
- **Date:** Long date: 2026年10月19日 (no leading zeros). Verified: Intl.DateTimeFormat('zh-CN', {dateStyle:'long'}) and {dateStyle:'medium'} both give '2026年10月19日'. copy-zh.md and both page drafts hard-code '2026 年 10 月 19 日' (with half-width spaces). If the date is ever generated by code, choose one convention.
- **Special sentences:**
  - *gender with {Name}/{Lender}*: No gender agreement on verbs or adjectives. Only the written pronoun 他/她 shows gender, and the site does not know it. Suggestion: Avoid 他/她 after a name placeholder. Repeat the placeholder or use 对方 (as the file already does).
  - *particles around {item}/{Name}*: Particles and nouns do not change form. The only issue is how it reads when a Latin-script name runs into Chinese text. Suggestion: Keep half-width spaces around Latin or number placeholders as in copy-zh.md; optionally wrap item names in 「」. Code must not add extra spaces when joining strings.
  - *word order around placeholders*: Counts and times sit inside fixed frames (请在 {left} 内回复). Fragments concatenated in English order break. Suggestion: Write each count sentence as one complete message with the placeholder inside it. Pre-format {left} and {amount} for zh.
  - *{listing / user}*: Cannot swap one noun into a shared template. Suggestion: Two full strings (举报这个物品 / 举报这个用户) or {target, select, listing {举报这个物品} user {举报这个用户} other {举报}}.
  - *measure words*: Each counted noun needs its own measure word: 人 (位 in polite text), 件, 个/条. Suggestion: Put the measure word in the translated message (# 件物品, # 人, # 条消息), not in code.
  - *counter {n} / 2,000*: No grammar issue, but the number locale is hard-coded to en-US. Suggestion: Format with zh-CN. The visible digits are the same. The limit text in 17.9 (消息最多 2,000 个字符) is already correct.

### Traditional Chinese (zh-hant)

- **Categories:** Correct as the builder reported. For zh, zh-Hant, zh-Hant-TW and zh-Hant-HK, the cardinal categories are only 'other', which covers every number: 0, 1, 2, 1.5, 1000. Ordinal is also 'other' only; ordinals use the prefix 第, e.g. 第 1 位. I confirmed this in Node 24 (ICU) with Intl.PluralRules: ['other'] for both cardinal and ordinal in all three locales. Nouns do not inflect. The count takes a measure word: 人 or 位 for people, 件 for items, 則 for listings and messages, 個 for characters.
- **Keys:** Only 'other'. Plain {count} interpolation works equally well. An exact '=0' branch is optional, for a natural empty or first-in-line sentence. Never build the Chinese string from the English 'person'/'people' or 'item'/'items' ternaries in queue-list.tsx (lines 51, 146, 150). Each language needs a whole message per string.
- **Sample: people ahead:** {count, plural, =0 {你前面沒有人了。} other {你前面還有 # 人。}}  Uses UI register 你. For queue-list.tsx:146 the full message would be: 已提供給排在你前面的人。{count, plural, =0 {你前面沒有人了。} other {你前面還有 # 人。}}  For :150: 借出中。{count, plural, =0 {你前面沒有人了。} other {你前面還有 # 人。}}  The builder's samples are valid ICU and correct; no change needed.
- **Sample: items in queue:** {count, plural, =0 {你的排隊清單是空的。} other {你的排隊清單裡有 # 件物品。}}  The =0 text matches the existing section 7 empty-queue copy (line 128: 你的排隊清單是空的). Valid ICU; no change needed.
- **Zero:** 0 falls into 'other'. 你前面還有 0 人 is grammatical but unnatural, so use '=0' or the existing empty-state copy. 你前面沒有人了 implies 'you are next in line'. That is true for the :150 'On loan' state, but should be checked against what the UI means in the :146 'offered to the person ahead' state. This is a native-review and product decision.
- **Fixed numbers:** No change with the number: 48 小時, 年滿 18 歲, 少於 6 小時, 2,000 個字元, 30 天. The file convention puts a half-width space between digits and CJK characters. The code should follow it if it builds these strings.
- **Numbers and currency:** Confirmed in Node 24 ICU: (12345.5).toLocaleString('zh-Hant-TW') gives 12,345.5 (comma grouping, '.' decimal, Western digits). Currency results for USD, TWD and HKD in each locale: zh-Hant and zh-Hant-TW give US$12.00, $12.00 (TWD shows as a bare '$', 2 decimals in standard format) and HK$12.00; zh-Hant-HK gives US$12.00, NT$12.00 and HK$12.00. So the builder was right. Format with Intl.NumberFormat(locale, {style: 'currency', currency: item.currency}) and pass the active locale instead of hard-coding 'en-US' or '$'. These are Node results; browser output was not checked.
- **Time left:** Do not use h/m. Use 5 小時 12 分鐘, 12 分鐘 and 2 天. Recommend 分鐘 over the builder's 分, because it matches existing copy (幾分鐘) and Intl output. In Node 24, Intl.DurationFormat('zh-Hant-TW') gives '5 小時 12 分鐘' for the short and long styles, but '5 小時12 分鐘' (uneven spacing) for narrow. So if Intl.DurationFormat is used, use style 'short' or 'long', not 'narrow', and check browser support first. Frames: 請在 {left} 內回覆 and 只剩 {left} 可以回覆了.
- **Date:** Last updated: 2026 年 10 月 19 日 (Gregorian calendar, no leading zeros, file spacing convention). This is the date in the copy file and in both page drafts. Intl.DateTimeFormat('zh-Hant-TW', {dateStyle: 'long'}) gives 2026年10月19日 without spaces (confirmed in Node). Pick one form if the date is ever generated by code. Do not use the ROC (民國) calendar. Hong Kong uses the same order.
- **Special sentences:**
  - *gender agreement with {Name} / {Lender}*: None. Chinese verbs, adjectives and pronouns do not change with gender. Suggestion: No branching needed. Keep avoiding 他/她; use the name, 對方 or 出借人.
  - *word order around {item} / {Name}*: Placeholders often sit mid-sentence, e.g. {Name} 傳了一則關於 {item} 的訊息給你。 Suggestion: Write each sentence whole with the placeholders inside. Never join English fragments around them.
  - *{listing / user}*: The two cases need different measure words: 檢舉這則刊登 vs 檢舉這位使用者. Suggestion: Use two full strings keyed by target type.
  - *count strings with classifiers*: The English '{n} item/items' pattern has no slot for the measure word (人, 件, 則, 個). Suggestion: Put the whole phrase in each language's message, e.g. {count} 件物品 and {count} 人.
  - *spacing around placeholders*: The half-width spaces around placeholders look slightly loose when the inserted value is Chinese. Suggestion: A native reviewer should decide, then apply the choice consistently.
  - *{amount} inside sentences*: A hard-coded '$' reads as NT$ to Taiwan readers. Suggestion: Format {amount} with the item's currency through Intl (see number_format).
  - *[message removed] and DELETE literals*: Database and code literals stay in English. [message removed] sits inside 「」 in the copy file and in privacy.md. Suggestion: Keep them as they are unless the code maps them (copy-zh-hant.md coordination notes 1 and 2).

### Spanish (es)

- **Categories:** Cardinal: one / many / other. I confirmed this in Node 24.15.0 (ICU 78.3, CLDR 48): pluralCategories = [one, many, other] for both es and es-419. one: n = 1 (1, 1.0, 1.00). many: e = 0 and i != 0 and i % 1000000 = 0 and v = 0, or e != 0..5. In practice this means exact millions (1000000, 2000000) and compact or exponent forms (1c6). select(1500000) = other. CLDR added 'many' for Spanish in CLDR 38 (2020), together with fr/it/pt/ca. Older ICU data shipped in browsers or polyfills has only one/other. other: everything else, including 0, 2-999999, 1.5, 0.5, 21, 100, 1000. Ordinal: only 'other'.
- **Keys:** one and other are required. ICU and FormatJS fall back to 'other' when 'many' is missing. Leave 'many' out while # is shown as digits. If you add a 'many' branch containing 'de' ('# de personas'), then 1000000 selects many and prints '1,000,000 de personas' (es-419), which is wrong with digits. Add 'many' only for strings that spell out 'millón' or use compact notation ('1 M de artículos'). Use exact-match =0 for empty states where code does not already branch. A 'zero' or 'two' keyword never matches in Spanish.
- **Sample: people ahead:** {count, plural, =0 {No hay nadie delante de ti.} one {Hay # persona delante de ti.} other {Hay # personas delante de ti.}}  For code: queue-list.tsx:146 (count >= 1 only) -> 'Se le ofreció a la persona que está delante de ti. {count, plural, one {Hay # persona delante de ti.} other {Hay # personas delante de ti.}}'. queue-list.tsx:150 -> 'Prestado. {count, plural, one {Hay # persona delante de ti.} other {Hay # personas delante de ti.}}'. Correction: the builder put an '=0 {Eres la siguiente persona.}' branch here. The code already handles ahead === 0 with a separate string ('On loan. You're next when it comes back.'), so that branch is never reached, and its text drops 'when it comes back'. Use a separate string for that case, e.g. 'Prestado. Te toca cuando vuelva.' item/[id]/page.tsx:102 -> '{count, plural, one {Hay # persona en la fila.} other {Hay # personas en la fila.}}'. The code already branches on inLine > 0, and the empty states are separate strings, so =0 is not needed there. These strings are drafts and are not yet in copy-es.md.
- **Sample: items in queue:** {count, plural, =0 {Tu fila está vacía.} one {# artículo en tu fila} other {# artículos en tu fila}}  For browse/page.tsx:49, which shows the catalog result count and not the queue: '{count, plural, one {# artículo} other {# artículos}}'. If a verb is added, it must agree: 'Queda # artículo' / 'Quedan # artículos'. Put the whole phrase inside each branch.
- **Zero:** CLDR puts 0 in 'other' ('0 personas', '0 artículos' are grammatical and plural). Prefer an explicit =0 branch with natural wording ('No hay nadie delante de ti', 'Tu fila está vacía') where the code does not already branch on zero. In queue-list.tsx and item/[id]/page.tsx the code already branches on zero, so keep those as separate strings. Decimals such as 1.5 are 'other'.
- **Fixed numbers:** '48 horas' / '48 h' (section 10 heading) is always plural. If the count becomes variable, it needs one/other (1 hora / 2 horas). '18 años o más' / 'menores de 18 años' never change. 'menos de 6 h': 'h' does not change, with a space before it and no period. '2000 caracteres' / '{n} / 2000' in copy-es.md follows RAE style. Intl gives '2000' for es, '2,000' for es-419/es-MX/es-US and '2.000' for es-AR/es-CO/es-CL (checked), so the literal limit and the formatted {n} must use the same convention. '30 días' is always plural.
- **Numbers and currency:** Digits 0-9. Checked with Intl in ICU 78.3. es-419, es-MX and es-US give 12,345.67. es, es-AR, es-CO and es-CL give 12.345,67. Base es does not group 4-digit numbers (2000). Format with Intl.NumberFormat in the user's locale (es-419 fallback) in place of the hard-coded toLocaleString('en-US'). Currency for USD: es-419 and es-MX 'USD 1,234.50', es-US '$1,234.50', es-AR and es-CO 'US$ 1.234,50', es-CL 'US$1.234,50' (no space), base es '1234,50 US$'. MXN in es-MX gives '$1,234.50'. A bare '$' reads as the local peso in MX/AR/CO/CL, so use style 'currency' with the item's currency code.
- **Time left:** 'h' for hours and 'min' for minutes. Never 'm', which means metres. Recommended: '5 h 12 min', '12 min'. Checked: Intl.DurationFormat('es') gives long '5 horas y 12 minutos' (singular '1 hora y 1 minuto'), short '5 h y 12 min', narrow '5h 12min'. NumberFormat unit 'hour'/'minute' with unitDisplay 'short' gives '5 h' / '12 min'. formatTimeLeft must become locale-aware. Use the long form for aria-label, and add a separate string for under one minute (e.g. 'menos de 1 min').
- **Date:** '19 de octubre de 2026' (dateStyle long, the same in es, es-419, es-MX, es-US, es-AR, es-CO, es-CL, checked). Label: '**Última actualización:** 19 de octubre de 2026'. Avoid numeric or medium dates on legal pages: medium gives '19 oct 2026' (es, es-419), '19/10/2026' (es-CO), '19-10-2026' (es-CL).
- **Special sentences:**
  - *gender agreement with {Name}/{Lender}*: Participles, adjectives and articles agree with the person's gender, which the site does not collect. ### Portuguese (pt-BR)

- **Categories:** Checked in Node (ICU 78.3, CLDR 48.0) with Intl.PluralRules('pt-BR'). ### Russian (ru)

- **Categories:** I verified these with Intl.PluralRules('ru') in Node v24.15.0.
