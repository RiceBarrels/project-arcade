# Internationalisation (i18n)

The site is written in English. English is the source language and the default
(`/en`). Ten more languages share the same pages under their own URL prefix.
Nothing in this setup needs an extra package.

| URL prefix | Language | `<html lang>` / hreflang | Direction |
| --- | --- | --- | --- |
| `en` | English (default, source) | `en` | ltr |
| `zh` | Simplified Chinese | `zh-Hans` | ltr |
| `zh-hant` | Traditional Chinese | `zh-Hant` | ltr |
| `es` | Spanish | `es` | ltr |
| `fr` | French | `fr` | ltr |
| `ar` | Arabic | `ar` | **rtl** |
| `tl` | Tagalog | `tl` | ltr |
| `vi` | Vietnamese | `vi` | ltr |
| `ko` | Korean | `ko` | ltr |
| `pt` | Portuguese (Brazil) | `pt-BR` | ltr |
| `ru` | Russian | `ru` | ltr |

User-written content (item titles, descriptions, messages, names, cities) is
never translated.

## Part 1: for translators (the dictionary files)

### Files

```
i18n/messages/en.json        generated from the code, do not edit by hand
i18n/messages/<prefix>.json  one per language: zh, zh-hant, es, fr, ar, tl, vi, ko, pt, ru
i18n/key-sources.json        generated: where each key is used (file:line), for context
content/legal/<prefix>/terms.md, privacy.md   the two legal pages (see "Legal pages")
```

To start a language, copy `en.json` to `<prefix>.json` and translate the
**values**. Never change a key.

### Structure

A flat JSON object. The **key is the English text itself**. The value is the
translation: a string, or an object of plural forms.

```json
{
  "Browse": "浏览",
  "Hi {name}, welcome back.": "{name},欢迎回来。",
  "Read the <link>terms</link> first.": "请先阅读<link>条款</link>。",
  "{count} people in line": { "other": "{count} 人在排队" }
}
```

- UTF-8, 2-space indent, no comments, no trailing commas.
- Keep the keys in the same order as `en.json` (alphabetical) so diffs are small.
- A key that is missing or `""` shows the English text. That's the safety net,
  not the goal: `bun run i18n:check` lists every missing key.
- Don't add keys that aren't in `en.json` (the check reports them as "extra").
- **Context keys.** A few keys start with a context and `::`, for example
  `"how it works step::Browse"` or `"item page heading::Queue"`. They are the
  same English word used in a different job from the plain key (`"Browse"` is
  the navigation tab). Translate only the text after `::`, worded for that job.

### Placeholders: `{name}`

- Text in curly braces is filled in by the code: `{name}`, `{count}`,
  `{amount}`, `{date}`... Copy each one into the translation **exactly**
  (same spelling, same braces, ASCII `{}`), in whatever position the grammar
  needs. Don't translate the word inside the braces.
- Every placeholder in the English must appear in the translation, and the
  translation may not add new ones. The one exception is plural forms below.
- Numbers, prices and dates arrive already formatted for the language (for
  example `1 234 $US` in French). Arabic uses Western digits (0-9) on this site.

### Tags: `<link>...</link>`, `<b>...</b>`

- Some strings contain tags that the code turns into a link or bold text, for
  example `Read the <link>terms</link> first.` Keep every tag, with the same
  name, wrapping the words that should be the link or the bold part in your
  language. Don't add, remove or rename tags.
- A tag like `<br/>` (self-closing) is a line break or an inline element: keep it.

### Plurals

A key whose English value is an object is a plural:

```json
"{count} items": { "one": "{count} item", "other": "{count} items" }
```

Translate it as an object with the plural categories **your language** uses
(Unicode CLDR / `Intl.PluralRules`), not the English ones:

| Language | Categories to fill in |
| --- | --- |
| zh, zh-hant, vi, ko | `other` |
| tl | `one`, `other` |
| es, fr, pt | `one`, `many`, `other` (`many` is only for millions; if you leave it out, `other` is used) |
| ru | `one`, `few`, `many`, `other` |
| ar | `zero`, `one`, `two`, `few`, `many`, `other` |

- `other` is required and must contain every placeholder, `{count}` included.
- Optional in every language: `"=0"`, used for exactly zero instead of the
  category your language's rules pick (French and Portuguese put 0 in `one`,
  which gives "0 objet"). Example: `{ "=0": "Aucun objet", "one": "{count} objet", "other": "{count} objets" }`.
- The `zero`, `one` and `two` forms may spell the number out instead of using
  `{count}` (Arabic often does), but may not add other placeholders.
- Example (Russian): `{ "one": "{count} вещь", "few": "{count} вещи", "many": "{count} вещей", "other": "{count} вещи" }`.

### Style

- Follow `docs/glossary.md` for fixed terms (queue, damage price, lender...).
- Same voice as the English: short, friendly, plain. No emoji, ever.
- The brand `project-arcade` and the stage label `pre-alpha` stay in English.
- Keep the address form consistent across the whole UI of your language.

### Checking your work

```
bun run i18n:check            # every language
bun run i18n:check fr ar      # only these
bun run i18n:check --allow-missing   # missing keys as warnings, other problems still fail
```

It reports, per language: missing keys, extra keys, placeholders or tags that
differ from the English, missing or unknown plural forms, and values of the
wrong type. It also checks the legal pages: a header with `title` and
`updated`, only the supported boxes, no HTML; and it warns when a translation's
date or structure (sections, bullets, numbered points, boxes) differs from the
English, which usually means the English changed since. Exit code 1 means
something needs fixing.

### Legal pages

The Terms of use and Privacy policy are long, so they are not in the
dictionaries. Each is a Markdown file:

```
content/legal/en/terms.md       the official English text (docs/copy-en.md sections 8 and 15)
content/legal/<prefix>/terms.md a translation
content/legal/<prefix>/privacy.md
```

Format: a small header, then a limited Markdown.

```
---
title: Terms of use
updated: 2026-10-19
---

::: draft
DRAFT: needs review by a lawyer before launch.
:::

::: summary
**The short version:** ...
:::

1. **Lead in bold.** Rest of the point.
2. ...

## Section heading

A paragraph. *Emphasis*, **bold**, `code`, [a link](/privacy).

- A bullet
- Another bullet
```

- `title` is the page heading (translate it). `updated` is the date of the
  English version the translation follows, as `YYYY-MM-DD` (the page shows it
  in the reader's language).
- Supported: `## ` headings, paragraphs, `- ` bullets, `1. ` numbered lists,
  `**bold**`, `*emphasis*`, `` `code` ``, `[text](/path)` links (site paths get
  the language prefix automatically), and the `::: draft` / `::: summary` /
  `::: note` boxes. Nothing else; HTML is shown as plain text.
- Keep `[TO CONFIRM ...]`, `[contact email]` and other bracketed placeholders
  as they are (translate the words inside only if the English ones would
  confuse a reader).
- If a language has no file, the English one is shown with a notice saying so.
  A translated page shows a notice that the English version is the one that
  counts.

## Part 2: for developers

### Where things are

| File | What |
| --- | --- |
| `lib/site.ts` | `LOCALES`, `DEFAULT_LOCALE`, `isLocale`, `LOCALE_COOKIE` (`pa_locale`) |
| `i18n/config.ts` | Per-language settings (html lang, Intl locale, dir, native name), `localePath`, `stripLocale`, `switchLocalePath`, `localeFromForm` |
| `i18n/core.ts` | `createTranslator` (lookup, placeholders, tags, plurals, number/money/date) |
| `i18n/msg.ts` | `msg()` / `msgPlural()`: mark strings for extraction without translating yet |
| `i18n/server.ts` | `getT()`, `getLocale()`, `alternates(path)`, `getClientMessages()` (server only) |
| `i18n/client.tsx` | `I18nProvider`, `useT()`, `useLocale()`, `useLocalePath()`, `useRouter()` (client) |
| `i18n/link.tsx` | `Link`: next/link that adds the locale prefix |
| `components/locale-switcher.tsx` | The switcher (desktop header, footer, phone Me page) |
| `proxy.ts` | `/` and locale-less paths -> cookie language or `/en`; unknown prefixes -> real 404 |
| `scripts/i18n-*.ts` | `bun run i18n:extract`, `bun run i18n:check` |

### Rules

1. **Every visible string goes through the translator**, including
   `aria-label`, `title`, `placeholder`, `alt` and metadata titles.
   - Server Component: `const t = await getT();` (from `@/i18n/server`). The
     component becomes `async`.
   - Client Component: `const t = useT();` (from `@/i18n/client`).
   - A component without `"use client"` that a Client Component imports is a
     Client Component: use `useT()` there and add `"use client"` if needed.
2. **The key is the full English sentence**, exactly as shown. Never build a
   sentence from pieces (`"Fee: " + x + " per day"`). Use placeholders:
   `t("Fee: {fee} (paid directly to the lender)", { fee })`.
3. **Markup inside a sentence**: `t.rich("Be the first to <link>list something</link>.", { link: (c) => <Link href="/list">{c}</Link> })`.
   A placeholder can be a node too: `{ name: <bdi>{user.display_name}</bdi> }`.
4. **Plurals**: `t.plural(n, "{count} person in line", "{count} people in line")`.
   `{count}` is filled in automatically. `t.richPlural` for plurals with markup.
   Dictionaries may add an `"=0"` form for exactly zero.
4b. **Same English, different job**: when one English word needs different
   translations in different places, give the less common use a context:
   `t.ctx("item page heading", "Queue")`, or `msgCtx("how it works step", "Browse")`
   outside a component. The key becomes `"item page heading::Queue"`; English
   shows "Queue". Tell the translators about new context keys.
5. **Strings defined outside a component** (constants, lib/ labels, Server
   Action errors): wrap in `msg("...")` and translate where shown: `t(label)`.
   `t(x)` with a non-literal argument is only allowed when `x` came from `msg()`.
6. **Server Actions can't read the locale** (`next/root-params` doesn't work
   there). They return `msg()` strings that the client shows with `t(...)`, and
   forms that redirect send `<input type="hidden" name="locale" value={t.locale} />`,
   read with `localeFromForm(fd)`. Never show raw Supabase error text: map the
   known error codes to messages.
7. **Links**: import `Link` from `@/i18n/link` and write site paths without a
   locale: `<Link href="/browse">`. Client navigation: `useRouter()` from
   `@/i18n/client` (adds the prefix), or `useLocalePath()` for a string.
   Server: `redirect(localePath("/login", await getLocale()))`.
8. **Metadata**: every page exports
   `generateMetadata` with a translated title and `alternates: await alternates("/its/path")`
   (all languages plus `x-default`; Google ignores an incomplete set).
9. **Numbers, money, dates, lists**: `t.number(n)`, `t.money(n, currency)`,
   `t.date(iso, opts)`, `t.list(["a", "b"])` (the language's separators and
   "and"), `t.lower(s)` (lower case by the language's rules). All use the page
   language with Western digits. Numbers in placeholders are formatted
   automatically.
10a. **User content in another script** (an English item title on an Arabic
   page): give the element `dir="auto"` (plus `ltr:text-left rtl:text-right`
   to keep it aligned with the page), or wrap inline names in `<bdi>`.
10. **Right-to-left**: use logical classes (`ms-`/`me-`, `ps-`/`pe-`,
    `start-`/`end-`, `text-start`/`text-end`, `border-s`/`border-e`,
    `rounded-s`/`rounded-e`). Arrows and chevrons that point "forward" or
    "back" get `rtl:-scale-x-100`. User names and the brand inside text go in
    `<bdi>` (string placeholders are isolated automatically on RTL pages).
11. **No async dictionaries for visible text**: dictionaries are bundled on the
    server and the client part arrives with the root layout.
12. After changing strings: `bun run i18n:extract` (updates `en.json`,
    `client-keys.json`, `key-sources.json`), then `bun run i18n:check`.

### How a request gets its language

- `/zh/...` is Chinese. The `[locale]` segment is the only source of truth.
- `/` and locale-less paths (`/browse`, `/item/<id>`) redirect to the language
  in the `pa_locale` cookie (set by the switcher), else `/en`. The browser's
  `Accept-Language` is never used.
- Switching language sets the cookie and loads the same path under the new
  prefix (query string and hash kept).
- Unknown prefixes (`/xx/...`) get a real 404.

### Fonts

Latin text uses DM Sans and Space Mono (preloaded). Vietnamese uses Be Vietnam
Pro for everything; Arabic adds Noto Sans Arabic; Russian adds Inter
(Cyrillic only). These load only on their own language's pages. Chinese and
Korean use the system CJK fonts. Korean uses `word-break: keep-all`.
See `app/fonts.ts` and the "Languages" block in `app/globals.css`.
