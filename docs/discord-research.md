# Discord and community research for project-arcade

Researched 2026-10-20 by session 4 (research). Read-only desk research; nothing was joined or observed inside a live Discord server.

**Evidence labels**
- **Strong**: official page I read myself, or several independent sources agree.
- **Medium**: one first-hand or official source, or a search-result excerpt of an official page I could not open.
- **Weak**: a third-party blog, a forum post, a single anecdote, or inference. Blogs marked "sells a bot" have a commercial interest.
- **Not found**: I searched and found nothing. Nothing below is filled in from guesswork.

**Important limit:** I did not find a Discord server run by Library of Things UK, any tool library, Buy Nothing or Freecycle. Buy Nothing runs on Facebook groups plus its own app, Freecycle and Freegle on their own platforms. So "how similar communities use Discord" is mostly **not found**; what exists is how they organise volunteers and rules on other platforms. Do not present any channel layout below as "what X does".

## 1. How similar communities organise volunteers, rules and disputes

### 1.1 Buy Nothing Project (Facebook groups + own app)
- Local groups are run by volunteer admins; the Project sets baseline rules and does not step into group conflicts, membership or growth decisions. Strong. https://buynothingproject.org/admin-agreement
- Admin duties: process the membership queue, moderate, enforce rules, post at least monthly. The Project archives a group if admins go over 30 days without posting or handling the queue, or allow commercial posts. Number of admins is not specified. Strong. Same source.
- Admins can add local rules in a separate, signed addendum; the core Rules, Description and 3 Questions stay unchanged. Strong. Same source.
- The 10 rules: legal only, no cruelty/harassment/hate, no stealing, no pressuring people in private messages, no buying/selling/trading/advertising, participate at your own risk (the Project, founders and admins accept no liability), follow local pinned norms. Strong. https://buynothingproject.org/10-rules
- The rules page does **not** address minors, in-person exchange safety, scams or disputes. Local groups handle those. Strong that the page is silent; I found no replacement official text.
- Complaints about an admin go to the Project via a form; it says it may have limited ability to act. Medium. https://help.buynothingproject.org/article/70-the-admin-of-my-buy-nothing-facebook-group-is-difficult-or-not-following-the-rules
- Press coverage describes heavy-handed local admins removing posts and banning members. Weak (one local story). https://dcist.com/story/23/02/21/buy-nothing-capitol-hill-take-my-sht-group-drama
- Gift-only: no money exchange at all. Strong. https://docs.buynothingproject.org/about
- Scam advice: **not found** in official material.

### 1.2 Freecycle / Freegle
- Freecycle: since 2009 new groups must join Freecycle's group system, giving the network oversight of local volunteer moderators, enforced by regional and global outreach volunteers. Medium (Wikipedia). https://en.wikipedia.org/wiki/The_Freecycle_Network
- UK moderators split off in 2009 to form Freegle over how groups should be run and the dismissal of long-serving moderators. Medium (Wikipedia). https://en.wikipedia.org/wiki/Freegle
- Freegle: autonomous volunteer-run local groups that affiliate if they meet basic requirements (free to join, free legal items only); registered society and exempt charity; own open-source platform; about 453 groups and 3.27M members (2021 figure); volunteer count shown as about 449 (2021) or about 1,000 (infobox), so inconsistent. Medium. Same source.
- One local Freecycle moderator describes strict practice: every post moderated, no selling, no animals, no borrowing, caps on "wants". Weak (one forum post; local, not network-wide). https://selfsufficientish.com/forum/viewtopic.php?p=131004
- Scam pattern reported by a moderator warning: people who post "wanted" get asked for money transfers; fake offers ask for delivery money. Advice: treat any request for money as suspicious. Weak (2013, republished). https://www.moneymagpie.com/save-money/freecycle-scams-two-new-ones
- A lesson here is governance: central control over volunteers caused a split.

### 1.3 Library of Things UK and local libraries of things
- Volunteer roles on the official site: host, thing fixer, ambassador, skill sharer, with discounted borrowing and training as the reward. Medium. https://content.libraryofthings.co.uk/shareware-volunteer
- Many branches are independent, volunteer-run schemes; contact the local one. Medium. https://www.waverley.gov.uk/council-updates/read-our-latest-news/save-money-and-reduce-waste-with-local-libraries-of-things
- Share Bristol volunteers check, clean, test and catalogue items each month. Weak-medium. https://www.bristol247.com/business/better-business/share-bristols-library-of-things-membership-marks-milestone/
- Any Discord, forum or Facebook group: **not found**.
- Rules on minors, scams and disputes: only from the lending policies of tool libraries (18+ or ID, borrower pays damage, right to refuse repeat offenders). Sources: https://www.westphillytools.org/lending-policy and https://lists.mcls.org/pipermail/michlib-l/2023-January/028563.html (minors cannot sign waivers, restrict to adults or get a parent).

## 2. Common Discord pitfalls for nonprofit / volunteer communities

### 2.1 Moderator burnout
- Discord's own safety guidance: moderating takes a toll; let mods step away; let teammates cover; mods pick channels they like and switch after a couple of weeks; keep a private staff channel to vent; run team events; know each mod's temperament. Medium (official safety pages, read via search excerpts). https://discord.com/safety/understanding-and-avoiding-moderator-burnout and https://discord.com/moderation/360058645534-311-understanding-and-avoiding-moderator-burnout
- Third-party: set limits early (nobody expected online all day), rotate hard tasks like appeals, check in after 14 days of silence, talk to mods when nothing is wrong. Weak. https://blog.communityone.io/discord-mod-team-guide-2026/
- Research note: peer support among moderators helps with harassment (Journal of Online Trust and Safety). Weak-medium, abstract only. https://par.nsf.gov/biblio/10320195

### 2.2 Rules too loose or too strict
- Official: Discord offers moderator guidance on writing moderator guidelines. Medium (excerpt only). https://discord.com/moderation/1500000178021-302:-Developing-Moderator-Guidelines
- Evidence of too-strict admins: the Buy Nothing story above (Weak). Evidence of governance conflict from over-control: Freecycle/Freegle split (Medium).
- Third-party: staff must follow the rules too; written internal guide before mods act alone. Weak.
- No quantified data on "too loose vs too strict" found.

### 2.3 Spam accounts and new-account gates (official)
Verification levels, from Discord's own safety page (Strong):
| Level | Requirement |
|---|---|
| None | none |
| Low | verified email (Discord recommends this for servers with a public invite link) |
| Medium | verified email and account older than 5 minutes |
| High | plus member of the server for more than 10 minutes (helps slow raids) |
| Highest | plus verified phone number |
Source: https://discord.com/safety/360043653152-Four-steps-to-a-super-safe-server (read directly). The help-center page https://support.discord.com/hc/en-us/articles/216679607 returned 403 to me.

Other official settings (Medium, from the help-center excerpt, which I could not open directly):
- AutoMod (Server Settings > AutoMod) can block messages with keywords before posting.
- Turn off "@everyone, @here and all roles" mentions for non-staff roles.
- Raid Protection (Server Settings > Safety Setup) alerts a channel and requires a CAPTCHA for new joiners for the next hour when a raid is detected.
Source: https://support.discord.com/hc/en-us/articles/10989121220631 and https://discord.com/safety/auto-moderation-in-discord and https://discord.com/blog/new-anti-spam-raid-automod-safety-update

## 3. Discord's official requirements

### 3.1 Community server
Requirements to enable Community (Medium; the help article https://support.discord.com/hc/en-us/articles/360047132851 returned 403 to me, so this comes from search-result excerpts of it):
- Verification level must require a verified email before members can message (members with roles are exempt).
- Explicit media content filter must scan media from all members.
- A rules channel must be set.
- A Community Updates channel must be set (Discord posts moderation announcements there; keep it staff-only).
- The server must follow the Community Guidelines.
2FA is **not** a Community requirement; it is a separate setting that makes moderators and admins have 2FA to take admin actions. The owner must turn on 2FA first. Strong (official safety page, section 2.3 link).
Explicit media filter can be set to all members, only members without roles, or off; age-restricted channels are exempt. Strong. Same safety page.

### 3.2 Age
- Discord Terms: users must be at least 13 and meet their country's minimum age. Strong. https://discord.com/terms
- Discord's guidelines set no general minimum age but require 18+ for adult sexual content; owners must age-restrict channels with explicit adult content. Strong. https://discord.com/guidelines
- Discord's country-specific age list is in a support article I did not open. **Not read.**
- Server owners have no stated age-verification duty in the Terms. Strong (silence in the Terms).
- Age assurance / teen-by-default: Discord announced teen-appropriate defaults for all users, delayed in February 2026 to the second half of 2026; one September 2026 secondary report says it launches 2026-09-23. Teen accounts lose access to age-restricted servers. Weak-medium, mostly secondary; verify before relying. https://discord.com/press-releases/discord-launches-teen-by-default-settings-globally , https://techcrunch.com/2026/02/09/discord-to-roll-out-age-verification-next-month-for-full-access-to-its-platform/ , https://www.gadgetreview.com/discord-is-moving-ahead-with-age-verification-despite-the-backlash
- Discord's safety guidance for under-18 accounts: tighter DM filters, limits on friend requests and server DMs. Medium. https://connectsafely.org/discord/
- Our lending side: minors cannot sign waivers (library lawyer comment, Medium), so project-arcade's own 18+ rule for borrowing should be mirrored in the server rules. Whether to restrict the Discord server itself to 18+: decision for the user, not researched further.

### 3.3 Rules that touch our use case (Strong, official guidelines https://discord.com/guidelines)
- Fraud, financial scams, phishing and counterfeit goods are prohibited.
- Selling or buying Discord accounts, servers, invite links and similar assets is prohibited.
- Promoting or coordinating child sexual content or sexual conduct with minors is prohibited; Discord reports to NCMEC.
- The guidelines I read say nothing about real-life meetups or in-person trades. **Not found** in Discord's rules; a search for it also found nothing.
- Discord does not monitor every server and relies largely on reports. Medium. https://gabb.com/blog/is-discord-safe-for-kids/ (secondary).

### 5.2 Per-candidate notes

- Note: `discord-mcp setup` defaults to preview mode, but running `serve` directly defaults to **allowing ordinary writes**. Medium (README). Set `MCP_WRITE_MODE=preview` explicitly.
- Partial tool enabling: README claims "guild and tool-category allowlists". The variable names for the category allowlist and per-tool disable are **没核到** (the docs pages I fetched did not list them). Whether `ban_member` is among the 31 dry-run-gated tools is **没核到**.

### 5.3 Recommendation

**Use `cappyeo/discord-mcp` (npm `@discord-mcp/cli`), pinned to one exact version (0.32.1 at the time of checking), with these conditions.** Evidence for the recommendation: Medium. Reasons:
1. It is the only one with documented guardrails: a write-preview mode, dry-run gating for destructive tools, a server-ID allowlist, and DM consent (Strong, official docs I read). Others have none that I found.
2. Its documented bot setup needs no privileged intent for default use and says not to use Administrator (Strong), versus barryyip0625 and glittercowboy which recommend Administrator or three privileged intents.
3. Token via the `DISCORD_TOKEN` environment variable is documented (Strong); it also has stdio and bearer-protected HTTP, whereas SaseQ's HTTP mode has no auth (open issue #40) and tristan's HTTP mode has none.
4. Package hygiene is better than the rest on paper: npm provenance attestation, no install scripts, repo URL matches (Strong, npm metadata). Active (commits 2026-10-19).
5. It covers all four needed jobs (channels, role/permission changes, messages, kick/ban) according to the README (Medium; I read the README's capability table and docs, not the full tool list at https://cappyeo.github.io/discord-mcp/tools/).

Setup conditions for 8号 / the user (do not skip):
- A **new, dedicated bot** just for this server, not the same bot as any other use. Own the Developer Portal account with 2FA on.
- Start with `MCP_WRITE_MODE=preview` and `ALLOWED_GUILDS=<our server ID>`; leave `MCP_DRY_RUN` on. Only switch to writes after reading a preview.
- Bot permissions: only what the current job needs (Manage Channels, Manage Roles, Send Messages first). **No Administrator.** Add Kick/Ban/Moderate Members only when we want the bot to do it, and consider keeping bans with a human moderator.
- Token only in the environment of the process that launches the MCP client; never in the MCP JSON config, never in the repo, never pasted in chat. Rotate it if it is ever shown.
- stdio only; do not run the HTTP mode.
- Run `discord-mcp catalog --check` (no token, no network) first, then `doctor --online`, as the README describes, before any write.
- Re-check the tool list for ban/delete and whether a category allowlist can disable them: this is **没核到** and matters for our "disable ban and delete" requirement.

Why not the others: SaseQ is the most popular but has no auth on its default HTTP mode and no safety features; barryyip0625's npm package is stale and asks for Administrator or three privileged intents; tristan-kkim cannot ban or edit role permissions and its README points pip at someone else's package; ExilProductions and jackglick have no license; glittercowboy's three-generic-tools design and Administrator advice make approvals hard; the two unnamed items could not be found.
